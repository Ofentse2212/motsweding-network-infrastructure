# Client Requirements

## 1. Client Overview

| Item | Details |
|---|---|
| Organisation | Motsweding Event Management |
| Location | Potchefstroom |
| Industry | Entertainment |
| Client ID | CLI-123 |
| Project ID | CMPG325-2026-123 |
| Assigned Addressing Block | 10.48.0.0/16 |

Motsweding Event Management is an entertainment organisation based in
Potchefstroom. The project requires the design and simulation of a
computer network that addresses the organisation's networking needs
while satisfying the specified technical challenge, design constraint,
and change request.

## 2. Project Objective

The objective of the project is to design, implement, and simulate a
functional computer network for Motsweding Event Management using Cisco
Packet Tracer.

The completed solution must provide appropriate connectivity between
network nodes, implement the assigned Router-on-a-Stick networking
challenge, satisfy the Point-of-Sale availability constraint, and
accommodate the client's change request without requiring a network
redesign.

## 3. Client Requirements

### 3.1 Network Connectivity

The network must permit successful data exchange between appropriate
network nodes.

### 3.2 Network Implementation

The network must be designed and simulated using Cisco Packet Tracer.

### 3.3 IP Addressing

The assigned addressing block `10.48.0.0/16` must be used as the basis
for the network's IP addressing plan.

### 3.4 Network Devices

The solution must include the necessary routers, switches, end devices,
and other required network nodes to provide the required connectivity
and functionality.

### 3.5 Network Services

Appropriate network connectivity and services must be provided for the
assigned client scenario.

## 4. Assigned Networking Challenge

The assigned networking challenge is **Router-on-a-Stick
(sub-interface Inter-VLAN routing)**.

The solution must configure, verify, and demonstrate Router-on-a-Stick
within the Motsweding Event Management network.

The implementation must also allow the configuration to be explained
and justified during the project demonstration.

## 5. Design Constraint — POS Availability

The Point-of-Sale (POS) systems must remain online even if the office
LAN fails.

This requirement must be addressed through the network architecture
and demonstrated through testing of the final Packet Tracer solution.

## 6. Client Change Request — CR1

The client has signed eight additional staff members in one department.

The network must accommodate these additional staff members without
requiring the network to be redesigned.

The IP addressing and network design must therefore provide sufficient
capacity to accommodate the change request.

## 7. Testing Requirements

The completed network must provide evidence of:

- Successful end-to-end connectivity between appropriate nodes.
- Successful configuration and operation of Router-on-a-Stick.
- Successful operation of the network according to the design.
- Important troubleshooting performed during implementation.
- A working Cisco Packet Tracer `.pkt` file that can be opened and
  reproduce the working solution.

  ## 8. Documentation Requirements

An individual GitHub portfolio must be maintained throughout the
project.

The portfolio should contain appropriate evidence covering:

- Client requirements
- Network design
- IP addressing
- Physical and logical topology
- Cisco Packet Tracer implementation
- Configuration
- Testing
- Screenshots and other evidence
- Troubleshooting
- Reflection

Meaningful commits should be used to demonstrate the development of
the project over time.

## 9. Project Success Criteria

The network design will be considered successful when:

- [ ] The solution is implemented in Cisco Packet Tracer.
- [ ] The `10.48.0.0/16` addressing block is used.
- [ ] Appropriate network connectivity is provided.
- [ ] Router-on-a-Stick is successfully configured and demonstrated.
- [ ] The POS availability constraint is satisfied.
- [ ] CR1 can be accommodated without redesigning the network.
- [ ] End-to-end connectivity is successfully tested.
- [ ] Important troubleshooting is documented.
- [ ] The final `.pkt` file reproduces the working solution.
- [ ] The GitHub portfolio contains the required project evidence.
- [ ] The individual video demonstrates the required components.
